# HELIOS - Human Evaluation and Life-Indication Observation System

**Intelligent Health Monitoring for Space Missions**

A complete Python + Streamlit application for astronaut health monitoring with integrated machine learning anomaly detection.

## Problem Statement

Long-duration space missions expose astronauts to radiation, isolation, confinement, altered gravity, and a hostile closed environment. These conditions can contribute to changes in cardiovascular health, sleep, behavior, immunity, and bone health. Astronauts must monitor their own health and recognize concerning changes. HELIOS collects and visualizes health indicators, uses machine learning to identify unusual patterns, explains its findings, and provides guidance for decision-making.

## Objectives

1. **Real Data Generation**: Create synthetic astronaut health data with realistic metrics and injected anomalies for demonstration
2. **Genuine ML Pipeline**: Implement unsupervised anomaly detection using Isolation Forest
3. **Explainable Predictions**: Provide feature-level explanations for all anomaly flags
4. **Premium UI/UX**: Design a cohesive space-themed interface with dark navy backgrounds, cyan and solar-gold accents
5. **Integrated Monitoring**: Combine data loading, anomaly detection, alerting, and visualization
6. **Comprehensive Testing**: Include pytest tests for all critical components
7. **Demo-Ready**: Provide a reliable demonstration that works immediately without hardware or external services

## Features

- **Mission Overview**: Astronaut profile selector, mission status, latest measurements, and data freshness
- **Health Monitoring**: Interactive historical charts, personal baseline comparisons, multi-metric dashboards
- **ML Intelligence**: Real anomaly detection with explainable predictions and top contributor analysis
- **Alert System**: Context-aware alerts with severity levels, explanations, and recommended actions
- **Mission Health History**: Timeline view of all anomalies, filterable by time range
- **System Information**: Data source, model state, training details, and evaluation metrics

## Dataset Provenance

### Synthetic Astronaut Data

The application uses **synthetic data** generated by `src/data/generate_health_data.py` for demonstration purposes:

- **3 Astronauts**: Commander Alex Vega, Dr. Maya Rodriguez, Lt. Kenji Tanaka
- **120 Days of Data**: ~1,089 total records generated (3 records per day per astronaut)
- **10 Health Metrics**: Heart rate, blood oxygen, blood pressure, body temperature, sleep duration/quality, physical activity, stress level, mood score
- **8% Anomalies**: 1,089 records with 87 intentionally injected anomalies
- **Data Quality**: Excellent (70%), Good (25%), Fair (5%)
- **Sources**: Wearable sensors (60%), Manual entry (30%), Simulated (10%)

**Statement**: Successful detection of these synthetic anomalies demonstrates the ML pipeline works correctly but does NOT establish clinical accuracy for real astronaut health assessment. The model should only be used as a helper tool and should never replace qualified medical professionals.

## ML Methodology

### Anomaly Detection Approach: Isolation Forest

- **Algorithm**: scikit-learn `IsolationForest`
- **Contamination**: 0.08 (8% - matches synthetic anomaly rate)
- **Features**: 10 normalized health metrics
- **Training Data**: 871 records (80% of total), validation: 218 records (20%)
- **Evaluation**: Validation set anomaly rate: 11.01%
- **Standardization**: Z-score normalization with median imputation for missing values

### Explainability

For each flagged anomaly, the system provides:

1. **Anomaly Score**: How unusual the pattern is (in decision function space)
2. **Feature Deviations**: Individual metric values vs. astronaut-specific baseline
3. **Standard Deviation Deviations**: Each metric's deviation in standard deviations
4. **Top Contributors**: Up to 3 metrics with the largest deviations
5. **Human-Readable Description**: Severity (slightly/moderately/significantly/extremely unusual)

### Limitations

- Unsupervised method (no labeled anomalies for real train/test)
- Synthetic data only (no validation against real astronaut health outcomes)
- Isolation Forest makes probabilistic assumptions not validated for clinical use
- Target detection: Sample features, not patient-level diagnosis
- Feature importance ≠ Clinical significance (e.g., detecting high stress ≠ diagnosing anxiety disorder)

### What It's NOT

This system does NOT:
- Predict cardiovascular events, stroke, heart failure
- Detect radiation injury, immune dysfunction, bone loss
- Diagnose mental health conditions (anxiety, depression, PTSD)
- Provide treatment recommendations or medical prescriptions
- Claim clinical accuracy or regulatory approval

It IS intended to:
- Flag unusual patterns for human review
- Provide context and explanations for unusual readings
- Serve as a monitoring aid, not a replacement for qualified medical professionals
- Demonstrate ML techniques in a relevant domain

## Health Risk Index (HRI)

The **Health Risk Index (HRI)** is a new composite metric that aggregates standardized deviations from astronaut‑specific baselines and the Isolation‑Forest anomaly score. It provides a single, interpretable score (0‑100) with three severity levels (low, moderate, high). The index is visualised as a gauge in the dashboard and helps researchers quickly assess overall health status across the mission timeline.

* No clinical weighting is applied – each metric contributes equally.
* The calculation is fully transparent and based on publicly available baseline statistics.
* The gauge colour follows the severity (green → orange → red).
* **Important**: The HRI is an experimental research tool only. It is not a medically validated metric and should not be used for clinical diagnosis or decision-making. It demonstrates ML techniques but does not establish clinical accuracy.
